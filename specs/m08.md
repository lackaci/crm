# M08 — Settings, secrets, and modes

## Goal
Define a safe settings screen and configuration loader for Mock, Dry-run, and
Live modes, including provider choices and secret handling.

## Exact files or areas expected to change
- `app/ui/`: add the settings screen and mode/provider controls.
- `app/`: add a small configuration loader and mode validation.
- `app/providers/`: connect provider selection without importing vendor code into
  business logic.
- `.env.example` or setup documentation: document names of required settings,
  but never include real values.
- Tests for configuration parsing, mode selection, and secret handling.

## Acceptance criteria
- A test can load Mock mode without network access or secrets.
- A test rejects an unknown mode and missing required settings for a selected
  non-Mock mode.
- The UI can display and change the selected mode and provider.
- No test, source file, log, or committed example contains a secret value.
- Sending is disabled in every mode at this milestone.

## Security/safety constraints
- Keep keys out of source code, SQLite, files, logs, and git.
- Use environment variables and the approved secret store described by PLAN2;
  do not print secret values.
- Default to Mock and use a separate test mailbox for later integration work.
- This milestone must not make external API calls.

## Out of scope
- Implementing a cloud LLM, Gmail, OAuth, or any other real API.
- Sending email or enabling Live-mode sending.
- Personal-data masking, attachment extraction, and hardening features.
- Adding dependencies during Phase 1.
