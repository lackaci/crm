# M11 — Gmail read-only

## Goal
Read a separate test mailbox and import messages, threads, and attachments
without requesting permission to write or send mail.

## Exact files or areas expected to change
- `app/providers/`: add the Gmail adapter behind `EmailProvider`.
- `app/db/emails.py` and `app/db/files.py`: store imported messages and
  attachments with stable links to customers.
- `app/ui/inbox.py` and related customer/file views: show synchronized data.
- Configuration/authentication areas from M08: support desktop login and
  read-only mode.
- Tests using a mock provider and a separate test-mailbox integration boundary.

## Acceptance criteria
- A mock test imports messages, threads, and attachments without network access.
- Imported emails can be displayed for the correct customer.
- Imported attachments are placed in the file store and can be traced to their
  source email.
- The integration requests read-only permission and has no write/send operation.
- A sync failure is visible in plain language and does not silently duplicate
  records.

## Security/safety constraints
- Use only a separate test mailbox; never develop against real customer mail.
- Store OAuth tokens only in the approved secret store, never in the database,
  files, logs, examples, or git.
- Keep Gmail behind `EmailProvider`; UI and business code must not import an SDK.
- Sending is disabled until M12, and real API work is not part of Phase 1.

## Out of scope
- Creating Gmail drafts or sending mail.
- Attachment OCR or LLM-based field extraction (M13).
- Cloud LLM implementation (M09).
- Broad mailbox administration, push notifications, or non-Gmail providers.
